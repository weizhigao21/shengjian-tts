# 独立批量推理 · v0.7.58

批量推理是独立后端模块，不替换现有 audio.cpp。首版适配 Qwen3-TTS Base 声音克隆：一个持久 Python 进程加载一份原始模型，使用官方列表生成接口一次处理多条文本，并复用参考音色提示。桌面与本地 API 不导入 PyTorch，发行包不包含该运行环境和原始权重。

## 使用

### 工作流整批入队（未发布源码）

更新工作流适配器后，单个声笺 API 且开启工作流批量模式时，将去除有效缓存后的待处理字幕一次入队。这样工作流原先的微批条数不会截断声笺的合批候选，例如 20 条兼容短句、声笺上限与启动门槛均为 8 时可按 8 / 8 / 4 调度。每条音频生成后立即下载并更新工作流进度；批量路径的一次张量调用仍须整批完成后才提交这一小批结果。

工作流暂停时停止服务后续调度，已经开始的调用继续完成并交付；其他任务可继续执行，恢复后处理剩余字幕。取消保留已下载音频。单次提交上限为 10,000 条，更大的字幕按此上限分批，同次运行归入同一工作流记录；多个 API、关闭工作流批量模式或旧服务使用原有处理方式。完整进度、交付和暂停接口见 [API.md](../API.md)。

### 配置独立后端

在「设置 → 批量性能 → Qwen 共享模型批量推理」选择已安装的 Base GGUF，点击 **一键安装并关联**。程序读取 GGUF 内部配置匹配 0.6B / 1.7B 原始权重，检测已有文件，下载缺少的独立 Python、PyTorch、Qwen SDK 和配套模型，完成后自动检查并保存关联。用户不需要预装 Python。也可以单独点击「下载运行环境」「下载关联模型」，或展开「高级手动配置」使用自选路径。

高级配置中的「每批最多」控制单次合批上限，「启动至少」控制自动加载新批量模型的门槛（2–8 条，不能大于上限，旧配置默认 2）。只有同任务、同代、同音色和兼容参数的文本才计入数量；不足时沿用原生引擎，不等待凑单。批量模型已经驻留时继续合并较少的尾段，避免为最后几条切换模型。显式 `inference_mode: batch` 可主动尝试两条合批；测速也直接测试选定的批量上限。

- Windows x64 自动安装将文件放在当前数据目录：`runtime/qwen-batch/` 保存便携 Python、CUDA / CPU 专用环境和 pip 缓存；`models/qwen-batch/规格/固定版本/` 保存原始权重。程序原位更新保留这些目录。
- 首次独立 Python 约 44 MB，PyTorch 等依赖另需数 GB；Base 0.6B 原始权重约 2.34 GB，1.7B 约 4.23 GB。点击安装前界面显示规格和保存位置。模型默认使用 ModelScope 魔搭，可选择 HF 镜像或 Hugging Face；所有来源均按内置官方目录的大小和 SHA-256 校验。魔搭使用其模型分支地址，但只接受与固定官方版本完全一致的文件。
- 「运行环境来源」与模型来源分开：默认「国内加速」，Python 优先通过 ghfast、GH-Proxy 下载固定的 Astral 官方附件；普通依赖优先清华 / 阿里云 PyPI，PyTorch 优先上海交大 / 阿里云轮子镜像，失败后尝试官方。也可选择「官方直连」，使用原 GitHub、PyPI 和 PyTorch 源。PyTorch / torchaudio 始终固定 2.9.0 的 `cu128` 或 `cpu` 构建，镜像不会改变计算版本；这些选项只作用于专用环境，不修改系统 pip 配置。
- 自动检测限于已导入的 GGUF、已保存路径、专用环境和标准 Hugging Face 缓存，不扫描整个磁盘或修改系统 Python。设备变更使用独立环境；默认 NVIDIA CUDA，驱动不可用时提示更新驱动或选择 CPU。
- Python 压缩包固定大小和 SHA-256，安全解压；模型固定官方提交并逐文件核对大小 / SHA-256，包含 speech_tokenizer 和文本分词器配置。下载只有用户点击安装 / 下载按钮后开始，打开界面、启动服务或轮询不会静默下载。
- 任务显示安装阶段、文件进度、近期下载速度。可暂停和继续；模型 `.part` 支持 HTTP Range 续传，依赖安装重试复用 pip 缓存。安装日志保存在 `logs/qwen-batch-install.log`。
- 完整文件优先复用；原始模型也可从标准 Hugging Face 缓存自动关联。安装期间不能修改高级配置，未完成或失败时保留原配置；若安装完成时正在推理，等待空闲后再应用。
- 首次打开和文件路径 / 环境文件变化时自动检测，下载期间轮询状态，完成后自动刷新关联与就绪提示。检测只检查元数据和依赖，不加载大模型；重复轮询不重复启动依赖检查。

原始模型与关联 GGUF 应对应同一规格；GGUF 不能交给官方 Python 后端直接加载。默认每批最多 2 条、总计 2400 字；可在高级配置调为 2–8 条。自动精度在 CUDA 上使用 FP16，在 CPU 上使用 FP32；2080 Ti 使用自动或 FP16。
启用后，现有 `/jobs` 和追加生成 API 会自动调度：

- 同一任务、同一生成批次内合并兼容短句；不跨任务 / 生成批次，保留框 ID、字幕顺序与各条结果。
- 生成语言可不同，模型、参考音色、参考原文及有效参数（含种子）必须兼容；不同种子分组，不静默修改参数。
- 孤立单条冷任务走现有引擎；批量模型已驻留时，兼容的末尾单条继续使用该模型，避免奇数条批次频繁切换。
- 不支持的模型 / 模式、超长文本、环境未就绪时使用现有引擎；批量运行报错或显存不足时，本生成批次回退到单实例原生引擎，不无限重复尝试。
- v0.7.54 起，单批等待上限按本批文本量估算（约 2.5 倍预估音频时长再加 20 秒，最少 45 秒，不超过预设超时），不再统一等满 600 秒。工作进程卡住会终止该进程并把这一批退回原生重试，任务不会长时间停在「运行中」；超时错误记录条数与实际等待秒数，可在 `logs/batch-*.json` 查看。
- 取消一批不会提交该批未完成输出；已完成内容保留。默认空闲约 120 秒后释放批量模型，手动释放引擎、识别和 AI 编辑也会释放它。

新后端与 audio.cpp 的随机采样、精度和实现不同，音频不保证逐样本相同。结果缓存按后端、原始权重版本、运行库版本及完整有序批次隔离；强制重生成与工作流临时音频仍遵守原有规则。若批次缓存不完整，重新生成整个张量批次，以免删除某一输入后改变其他输入的随机数位置。

## 查看实际推理状态

工作区右上角持续显示当前服务的实际执行状态，语音创作和工作流页面均可看到：

- **原生引擎 / Qwen 批量 · 本批 N 条**：正在执行的后端，区分准备中、生成中和取消中。生成中包含该次调用的模型加载与音色准备，不代表始终执行 GPU 运算。
- **原生引擎 · 已回退**：批量失败后改走原生，使用提示色；悬停可看任务 ID、片段编号和回退原因。未组成批次的正常原生调度可查看调度原因。
- **空闲 · 批量已就绪 / 批量模型驻留**：环境可用或模型已加载，均不表示正在批量生成。最近一次处理仅代表当前服务会话，不冒充当前活动。
- **上次缓存命中**：复用成品音频，本次没有执行推理；缓存来源引擎可在提示中查看。语音识别、编辑和速度测试会显示各自状态；断连后不保留旧的运行提示。

生成记录中的「推理引擎」列按每条结果保存的 `inference` 元数据展示原生、批量及批大小；缓存显示「缓存」，提示说明来源。旧记录没有元数据时显示「未记录」，不猜测引擎。

状态随原有约 1.8 秒的服务轮询刷新；`GET /health` 的 `active` 包含 `backend`、`batch_size`、`phase`、片段和调度 / 回退原因，`last_execution` 是会话内最后一次处理，`inference.loaded` 为批量模型驻留状态。`inference_benchmark` 只含测速进度，不返回完整报告。不新增状态请求或遍历历史库。

## 编码预测专用循环

「设置 → 批量性能 → 高级手动配置 → 编码预测加速」默认开启。独立 CUDA 后端在 qwen-tts 0.1.1 / Transformers 4.57.3 上检查模型结构与生成配置，将 Talker 内部固定 15 步残差编码预测改用专用循环，复用采样处理器，省去每个音频步的通用生成准备和结束判断。保留原模型 forward、KV 缓存、温度、Top K / Top P、采样算法和种子；不修改已安装 SDK 或权重。

未知版本、不同模型结构、额外 logits 约束、非固定步数、附加参数及 CPU 使用 SDK 原循环，不静默丢弃约束。专用循环运行异常仍由现有批量失败机制回退原生引擎。关闭后点击「检查并应用」，下一次加载使用原循环，无需重新下载。

每条生成记录的 `inference.predictor_mode`（`fixed` / `standard` / `mixed`）表示实际路径，另有实现版本、调用与回退次数、原因。状态和记录悬停提示、设置页上批结果可查看；复用成品缓存时仍明确显示缓存来源。健康状态不将设置开关冒充实际加速。测速报告保存 `predictor_fastpath` 和各轮实际 `predictor_modes`。

`batch_inference/qwen_fastpath.py` 是单独模块，作为源码与外部工作进程一起打包；桌面和 HTTP 服务不导入 PyTorch、Qwen SDK 或 Transformers。缓存签名包含开关和实现版本，改版后重新生成，不用旧音频证明新循环的性能。

## CUDA Graph 实验（未发布，默认关闭）

源码已增加 `predictor_cuda_graph: false`。实验开关位于批量性能的高级配置，需要先启用专用循环。已在 RTX 2080 Ti / PyTorch 2.9.0+cu128 完成真实 GPU 验证，现有 v0.7.50 包不包含此模块。

`qwen_cuda_graph.py` 将现有固定循环的 GPU 操作录制后重放，保留模型、采样及 KV 计算；输入每次复制，输出返回独立存储。每个新组合先预热、录制并核对编码和随机数位置，准备过程恢复原 RNG 状态。图按输入形状 / 布局、设备、精度和采样参数分开，最多驻留两个；近期失败组合暂不重复尝试，最多保留八个失败原因。空闲显存不足 512 MiB 时保留专用循环。

v0.7.54 起，遇到新的批大小会先释放最少使用的图并归还缓存块，再判断空闲显存。此前上一张图的缓存池会占满驱动可见显存，导致新形状（典型是 20 条拆成 8 / 8 / 4 的最后一组）整批退回无图路径。本机实测尾批由 1.74 秒 / 条降到 0.90 秒 / 条，20 条热模型合计约 16.3 → 12.7 秒。

可恢复的录制失败不阻断专用循环；随机数恢复失败或 CUDA 上下文异常不在原进程盲目重试，沿用批量工作进程退出与原生引擎回退。初始适配范围为 PyTorch 2.9.0、CUDA FP16、1–8 条；是否可用仍须在目标显卡验证。

结果增加 `predictor_graph_captures`、`predictor_graph_replays`、`predictor_graph_fallbacks`、`predictor_graph_reason`。只有实际重放时才报告 `predictor_mode: graph`，部分图加速报告 `mixed`；设置开关不代表已获得提速。录制预热和校验调用不计为实际重放次数。

2026-10-17 本机验证已完成：

1. 1 / 2 / 4 / 8 条、三套采样配置、三个种子共 36 组，编码与 RNG 位置均一致，均实际执行图重放。
2. 同音色同参数的中文 / 中英混合各 20 条，按 8 / 8 / 4 合批，两种实现均预热后按固定循环、图、图、固定循环的顺序交替计时。中文平均 14.27 → 7.15 秒，双语 17.21 → 8.58 秒；对应 WAV 逐条字节一致。
3. 测速期间无新增录制；两张图额外常驻分配约 18.35 MiB。真实工作进程取消约 0.10 秒后退出，无取消任务输出，重新启动后图路径正常生成。注入的显存保护 / 可恢复录制失败保持固定循环，编码和 RNG 不变。

完整方法、逐轮数据、首次准备耗时及验证边界见[验证报告](CUDA_GRAPH_VALIDATION.md)。这些数字仅代表本机模型、短句和批大小；其他显卡、精度、长文本及模型规模未据此验证。实验仍默认关闭，本轮未打包或原位替换程序，也未修改用户配置。

## 速度对比测试

安装就绪后，在同一页面的「速度对比测试」选择声音预设，点击「开始测速」。可选择中英双语、中文或英文，每组均为 20 条固定短句；双语组为 10 条中文和 10 条英文。热模型重复 1–3 组，默认 1 组；原生 / 批量两种后端各运行一组首组和一组热模型，默认总计生成 80 段测试音频。仅支持当前已关联的 Qwen Base 声音克隆预设、兼容的语言 / 语速和参数。

- 原生基线为 audio.cpp 单实例逐条生成，使用现有适配器；批量侧按当前每批条数和字数限制分组。两侧使用同一参考声音副本、原文、文本、语言和有效生成参数，固定种子 1234，每条最多 256 tokens（预设上限更小时保留其限制）。不更改保存的预设。
- 每个后端从新进程开始，先测一整组含模型加载的用时，再用同一进程和热模型完成后续组。这里只控制进程和模型驻留，不清空操作系统文件缓存，因此不将其称为磁盘完全冷启动。
- 热模型用时、音频时长按每组平均；界面显示热模型每条平均耗时 = 整组耗时 / 20，多组重复时按总耗时 / 总条数计算，不代表单条延迟。报告中 `sample_count` 记录每组条数，首组、各热模型组及热模型汇总均包含 `seconds_per_item`（秒 / 条）。RTF = 总生成秒数 / 总音频秒数，越小越快；吞吐 = 生成条数 / 秒。倍率 = 原生组耗时 / 批量组耗时，大于 1 代表该组工作负载中批量更快。两种模型的精度和采样实现不同，音频长度、内容完整性和质量可能不同，需结合时长和实际输出判断。
- 测试绕过成品音频缓存，仍会自然复用热模型和后端内部音色特征。某后端报错时保留错误和另一侧结果；批量侧不回退到原生后伪装成批量测速，不对失败或取消的对比计算倍率。
- v0.7.54 起，模型规范声明但只对原生引擎生效的参数（`stream_chunk_policy`、`stream_frames_per_event` 属于流式推送分块，`voice_id` 属于 CustomVoice 内置音色）不再阻止测速：它们不改变 Base 克隆的音频样本，批量侧也不转发。报告中记为 `ignored_options`，界面摘要显示「不参与对比的参数」。当前模型未声明、已不生效的历史参数只从测试快照剔除，不改写预设；其余无法表达的声明参数仍会拒绝并列出参数名。
- 开始前需完成 / 取消已有生成、识别、编辑、安装及排队任务。测试保留引擎，新提交的生成等待测试结束；测试中不可改引擎性能或模型配置。可以随时取消，服务退出也会取消并释放测试进程。
- 测试不写入作品、生成记录或成品缓存。临时 WAV 验证后清理，最近报告保存在 `benchmarks/latest.json`，日志在 `logs/benchmarks/测试ID/`。界面显示实时进度，支持复制 JSON 报告；重启后仍能查看最近报告。

### 本机 20 条实测 · 2026-10-16

RTX 2080 Ti（11 GB），Qwen3-TTS 1.7B Base，原生 BF16 GGUF 与对应官方原始权重；CUDA、独立后端精度 auto、每批 2 条、CPU 线程 8。使用同一参考音色和 10 中 / 10 英短句，种子 1234、每条上限 256 tokens，各测一组首组和一组热模型，不读取成品缓存。独立环境为 PyTorch 2.9.0+cu128、qwen-tts 0.1.1。

| 后端 | 首组 20 条（含加载） | 热模型 20 条 | 热模型每条平均 | 热模型音频时长 | 热模型 RTF |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 原生单实例 | 28.04 秒 | 23.44 秒 | 1.17 秒 / 条 | 55.20 秒 | 0.425 |

| 批量 8 条 · 8 线程 | 20.52 秒 | 1.03 秒 | 59.20 秒 | 0.347 |
| 批量 8 条 · 1 线程 | 21.16 秒 | 1.06 秒 | 59.20 秒 | 0.357 |

本次每批 8 条相比原生减少约 31% 耗时，相比每批 2 条吞吐约为 2.76 倍；降为 1 个 CPU 线程没有改善。不同批大小会改变随机数的消耗顺序和输出音频，固定种子不保证跨批大小逐字节一致，不能只比较更短音频的耗时。上述结果只代表本机短句负载，不是所有模型、设备和长度的通用结论。

2 条批量中，子码本预测调用约占整组 70% 耗时，音频解码不到 5%；子码本计时是包含等待 GPU 的主机墙钟时间，嵌套在 Talker 内，不能解读为 70% 的计算发生在 CPU。8 条时 PyTorch 保留显存约 8.46 GiB，因此未把 8 条设为所有用户的默认值。对于这台机器，可设置上限和自动启动门槛均为 8；小任务保留原生，已驻留批量模型继续完成尾段。

本轮只采用已验证的合批和选路调整，实验子模型替换未进入产品。更深入的优化可针对固定长度子码本生成和小算子调度；[vLLM-Omni 的实现说明](https://github.com/vllm-project/vllm-omni/blob/main/docs/design/qwen3_omni_tts_performance_optimization.md)也将这部分列为重点。不能直接将其其他硬件上的数字用于本机；[FlashAttention 官方支持说明](https://github.com/Dao-AILab/flash-attention#nvidia-cuda-support)区分了主线 FA2 与 Turing 专用实现。

随后使用正式适配器、去掉分段计时插桩，再次完整运行首组和热模型组：原生热模型 29.24 秒（1.46 秒 / 条），每批 8 条为 19.21 秒（0.96 秒 / 条），耗时减少约 34%，吞吐约为 1.52 倍。首组分别为 34.31 / 32.91 秒；新进程不等于清空系统文件缓存。该报告可在测速页查看，测试结束释放引擎。

## 高级命令行安装

在专用环境中安装，不覆盖系统 Python 或声笺配置。建议使用 Python 3.10–3.12。安装脚本默认只显示计划；加 `--install` 后才联网安装。下面示例以当前使用的 1.7B Base 为例，需要额外下载 PyTorch 和原始权重。

```powershell
python scripts/setup_qwen_batch.py --target "G:\models\qwen-batch-env" --download-model 1.7B --model-dir "G:\models\Qwen3-TTS-1.7B-Base"
python scripts/setup_qwen_batch.py --target "G:\models\qwen-batch-env" --download-model 1.7B --model-dir "G:\models\Qwen3-TTS-1.7B-Base" --install
```

脚本从官方 PyTorch CUDA 12.8 索引安装 torch / torchaudio 2.9.0，再安装 qwen-tts 0.1.1，从 Qwen 官方 Hugging Face 仓库下载原始模型；下载可继续使用已有文件。CPU 环境加 `--device cpu`。已有原始模型时省略下载参数；已有独立环境时可直接在设置中选择。Python SDK 首次加载可能需要较多时间和内存；模型加载仅访问本地文件，不在生成请求中自动下载。该环境与模型保存在自选目录，程序原位更新不会覆盖。

安装脚本与说明也包含在 Windows 分发包中；此高级脚本需要本机已有 Python。推荐直接使用设置页的一键安装，它会下载独立 Python。
源码目录中的脚本位于 `scripts/setup_qwen_batch.py`；Windows 分发包中的脚本位于 `docs/setup_qwen_batch.py`，在解压目录运行示例时将命令中的 `scripts/` 改为 `docs/`。

## API

| 接口 | 用途 |
| :--- | :--- |
| `GET /inference/backends` | 原生 / 批量后端能力、是否就绪、未就绪原因、是否已驻留。 |
| `GET /settings/batch-inference` | 配置、运行库版本、上批统计和近期回退；新增 `setup`，含本地关联候选、目标目录、大小和安装任务状态。 |
| `POST /inference/setup` | `{ "action": "all", "source_model": "已导入GGUF路径", "device": "cuda", "source": "modelscope", "runtime_source": "mirror" }`，202 异步安装。模型来源为 `modelscope / mirror / huggingface`；运行环境来源为 `mirror / official`。action 支持 `all / runtime / model / detect`；detect 仅本地检测和关联。 |
| `POST /inference/setup/pause` | 暂停当前专用环境 / 模型安装；已有文件保留。 |
| `GET /inference/benchmark` | 可选预设、就绪原因、测速进度和最近报告；`GET /settings/batch-inference` 也返回同一 `benchmark` 快照。 |
| `POST /inference/benchmark` | 202 异步测速：`{ "voice_id": "预设ID", "workload_name": "bilingual", "warm_rounds": 1 }`。文本组支持 `bilingual / zh / en`，热模型组数 1–3。 |
| `POST /inference/benchmark/cancel` | 取消测速并释放测试引擎，保留部分报告。 |
| `PUT /settings/batch-inference` | 保存独立环境、模型关联、设备、精度与批大小；活动推理期间拒绝更改。 |
| `POST /inference/plan` | `{ "voice_id": "预设ID", "texts": ["你好", "Hello"] }`；只读预览该预设的路由与批大小，不创建任务 / 加载模型。 |
| `POST /jobs`、`POST /jobs/{id}/generate` | 新增可选 `inference_mode: "auto" | "native" | "batch"`，默认 `auto`；`batch` 表示优先尝试，无法合批时仍返回原生结果及原因。 |

其他原有字段、轮询、取消、重试、工作流交付 API 保留。每条结果新增 `inference_mode` 与 `inference`；后者记录实际后端、批大小、整批耗时、模型版本与缓存状态，原生回退时记录原因。批量结果的 `generation_seconds` 是该条等待整批完成的耗时，不是独立测得的单条 GPU 时间。
`/health` 的能力列表包含 `batch_inference` 和 `inference_plan`，`inference_api:1` 表示接口版本；能力存在不代表原始模型或独立环境已安装，应再检查后端的 `ready` 与 `reason`。

## 模块与验证

`batch_inference/policy.py` 处理兼容性，`backend.py` 处理配置与选择，`process.py` 管理可取消的持久进程，`qwen_worker.py` 调用官方 SDK，`execution.py` 对接队列、缓存与文件交付。`discovery.py` 做本地规格识别和配对，`provisioning.py` 管理隔离安装、校验与取消。`benchmark.py` 管理独占测速、快照、无成品缓存的冷 / 热运行和报告。独立设置组件位于 `desktop/settings/batch_inference.py`，API 位于 `http_api/inference.py`。

自动回归覆盖队列、接口、真实子进程 IPC，以及 SDK 的列表输入 / 提示缓存调用契约；测试替身不代表真实模型性能。原始模型未安装时不能宣称已获得 GPU 加速收益，应在安装后用相同字幕比较总耗时、输出质量、模型冷 / 热启动及显存峰值。

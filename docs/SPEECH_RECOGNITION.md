# 语音识别 · v0.7.89

从「语音创作 → 语音识别」进入。把音频或视频拖到页面上，或点击「导入音视频」选择文件，拖入后立即显示文件名和「导入中」，无需等待解码或识别完成；识别完成后点击左侧任意一行即可播放对应片段。文章与对话的原有流程不受影响。

第一版只读取音频，不修改用户的原文件；PCM WAV 导入时复制到数据目录，其他编码通过随包提供的 Qt / FFmpeg 在独立进程转换为 PCM WAV；采样率和声道保持原音频解码后的值，无需另外安装 soundfile 或 FFmpeg 命令。

视频不是另一种识别流程，只是声音装在容器里：同一个解码器把第一段音轨取出来写成 PCM WAV，之后识别、对齐、点行播放全部复用音频路径。原视频不被读取后写回、不被转码，也不拷进数据目录。

## 第一版功能

| 操作 | 行为 |
| --- | --- |
| 导入 | WAV / FLAC / MP3 / M4A / AAC / OGG / OPUS / WMA / AIFF / AIF，以及 MP4 / MKV / MOV / AVI / WEBM / WMV / FLV / TS / 3GP 等视频；拖放或选择文件，PCM WAV 保留副本，其他编码转换为私有 PCM WAV，视频只取第一条音轨，原文件不变。 |
| 识别 | 使用引擎内的 ASR 模型转写文字，中文结果自动补标点；可选择语言或自动判断。 |
| 分行 | 按标点与停顿切分，每行不超过 24 字或 8 秒，空格分词的语言（英语等）放宽到 42 字；句末标点必定换行，从句标点只在行较长时换行。 |
| 点行播放 | 点击某一行播放该行的时间范围；再次点击同一行停止，勾选「连续播放」可依次播完。 |
| 精确时间 | 安装了强制对齐器、原文和语言可用时使用词级时间戳；未安装或对齐失败时保留文字、估算每行时间并提示。 |
| 导出 | 导出 SRT 或 TXT 字幕，或复制全文。有译文时会多出一个「导出中文字幕」按钮，只写中文译文、不混入原文，时间码沿用原字幕。 |
| 声音入库 | 右键识别行保存所选音频与原文到声音库；可按住 Shift 选择连续多行，或右键当前音频名称保存整段录音。 |
| 管理 | 重试、取消、删除记录；重命名只影响显示名称。最近作品统一展示文章、对话、音频编辑与识别任务，用不同图标区分，点击回到对应记录。 |

## 需要哪些模型

识别与对齐都走程序内置的统一引擎，跟随「设置 → 推理引擎」中选择的计算设备，不需要另装 Python 或外部框架。

| 用途 | 模型 | 说明 |
| --- | --- | --- |
| 文字转写 | Qwen3-ASR 0.6B Q8_0 | 必需。点击识别模型旁的「下载 / 管理」，定位到对应模型分类列表；下载或导入后自动出现在下拉框中。 |
| 词级时间 | Qwen3 强制对齐器 0.6B Q8_0 | 可选。点击时间对齐旁的「下载 / 管理」，定位到对应模型分类列表；安装后每行时间精确到词，未安装时按标点估算。 |

下载复用「设置 → 模型」中的下载器，可选择精度与下载来源、查看进度和暂停续传；点击入口不会直接下载大文件。若列表为空，请先安装或更新统一引擎，再点击「扫描支持模型」。

识别模型按引擎的 `model_specs` 任务声明自动登记为识别模型，只出现在识别模式，不会成为可选音色，也不会创建声音预设。

## 自动语言与异常恢复

v0.7.41 修复自动判断语言时对齐器提示缺少原文 / 语言的问题。audio.cpp v0.9.1 的简化转写接口即使请求 `verbose_json` 也只返回文字与耗时，因此优先使用保留检测语言的 `/v1/tasks/run`。通用接口不可用时回退到转写接口；如果仍没有检测语言，保留文字并提示手动选择语言后重试。

界面可继续选择「自动判断」，对齐使用检测到的具体语言；手动选择的语言优先，程序统一把 `zh` / `en` 等代码转成原生模型的 `Chinese` / `English` 等名称。旧失败记录在升级后点击「重新识别」即可重试。

静音或没有文字时跳过对齐并提示；语言未知、不在对齐器支持范围或对齐失败时保留识别文字，显示时间估算提示。估算时间可用于大致定位；需要精确定位时请检查模型、选择语言或缩短音频后重试。长音频即使未安装对齐器也会按 45 秒窗口逐段识别，避免整段请求漏字；没有对齐器时只跳过对齐请求，时间仍按标点估算。取消仍按已取消处理。

## 时间与分行

引擎给出的词级结果带有帧号与秒字段。秒字段按输入采样率换算，实测 `48 kHz` 输入时会偏小为真实值的三分之一，因此程序统一使用帧号除以 `16 kHz` 还原时间；只有在没有帧号时才回退到秒字段。

对齐器返回的词只包含字符，句读标点会被丢弃，中文和英文都一样（英文的 `position.` 同样只回来 `position`）。程序先把标点贴回其前一个字符，再据此分行，避免长句被长度上限硬切。小数的句点单独判断：前后都是数字时不作为句末标点，`3.5` 不会被拆到两行。

## 连续重复清理

ASR 在音乐、掌声或持续噪声上可能进入解码循环：一段没有台词的音频被反复吐成 `oh, oh, oh, ...`，对齐器仍会忠实给每个词分配时间，分行后就成了几十行几乎相同的字幕。这不是分行或对齐在复制文本——原始识别结果里就已经有几百个重复词。

程序在识别完成、分行之前做一次清理：同一词连续出现 6 次以上时只保留第一次；对齐失败、按标点估算成整段的分行结果，则在每行文本上再压缩一次；相邻且完全相同的行连续 3 行以上只保留一行。只处理连续片段，台词里分散出现的正常重复不受影响。

单文件识别和批量识别默认开启。批量页的「清理连续重复」开关可在建批次时关闭；关闭后保留 ASR 原始输出，适合确实需要逐字保留连续重复的实验素材。识别记录的 `dedupe_removed` 表示本次清掉的重复数量，`warning` 里也会写明。

## 保存到声音库

右键一条识别结果，选择「保存到声音库…」，程序按该行的时间范围准备独立 WAV，并自动带入原文与名称。在窗口中可试听、改名、核对原文，确认后保存到「声音库 → 参考声音」。

v0.7.43 起，试听波形随实际播放进度变色，按钮显示「停止试听」；再次点击、播放结束或出错后清零。更换音频会停止该窗口的旧试听，不影响其他来源正在播放的声音。

按住 Shift 可选择连续多行，保存从首行开始到末行结束的完整连续音频；右键「当前音频」名称可保存整段录音。参考声音仍需 1–60 秒，时长不合适时菜单禁用并提示改选识别行。

右键不会开始播放。估算时间的片段会提示先试听核对：长录音可能超出对齐模型上限，此时仍可保存片段，但原文与实际声音应在窗口中确认。取消不会创建库记录，临时裁剪文件会清理；保存后的副本独立保留，删除原识别记录不会影响声音库。

## 批量识别

创建首页的「批量识别」卡和识别页右侧「批量识别」分组的「打开批量识别…」按钮都会进入独立的批量模式页：一次选择多个音频或视频，按列表顺序逐个识别，每完成一个就自动把字幕写回**该文件所在的文件夹**。批量不是另一套识别流程，每一项仍创建普通识别记录（带 `batch_id`），因此点行播放、查看原文、再次打开记录都与单文件一致。

批次在最近作品 / 任务目录中只占一条记录（类型为「批量识别」，标题带文件数），批次的子会话不会再零散地排在侧栏；点击这一行即可回到批次，查看全部文件。批次页左侧是队列表格，右侧是选中文件的只读字幕预览：原文字幕优先读取已导出的 SRT/TXT，文件不在了则从识别记录生成；「译文」标签读取识别记录里由外部 Agent 回写的译文，并可单独「导出中文字幕」。在「字幕文件 / 译文」里点击任意一行会按该行时间码播放对应音频，再点同一行停止；页面还提供批次 ID 复制和「复制 MCP 指令」，方便把整批交给外部 Agent 翻译。

| 行为 | 说明 |
| --- | --- |
| 添加与开始 | 最多 200 个文件；开始前统一校验存在性与后缀。重复路径自动去重，不支持的格式在创建批次前就拒绝，不会留下半批记录。 |
| 连续重复 | 默认开启「清理连续重复」：连续重复词只留一次，相邻重复行合并，专门处理 ASR 在音乐/噪声上的解码循环；建批次前可关闭，批次创建后按记录中的开关执行。 |
| 顺序执行 | 前一个识别结束后才开始下一个；引擎在整批期间保持占用，单文件导入、配音生成、AI 音频编辑会等待，不会在两段之间插队。 |
| 自动导出 | 默认 SRT，也可选 TXT 或 SRT + TXT。导出位置取 `source_path` 的父目录；文件被移动后仍写到它记录的原目录。 |
| 同名保护 | 目标 `<文件名>.srt` 不存在时直接写入；已存在且内容完全相同就复用；内容不同则保留用户文件，另写 `<文件名>.识别字幕.srt`。重复跑同一批不会产生 `(2)` 副本，也不会覆盖手改字幕。 |
| 失败隔离 | 单个文件解码失败、识别失败或导出失败只记在该项上（状态为「完成 · 导出失败」或「失败」），队列继续；已成功的项不受影响。 |
| 停止与继续 | 「停止」取消当前识别并把未处理项标为已跳过；停止后可从失败或未完成项继续。导出失败不会自动重试，也不属于「重试未完成」；选中该行后在右侧查看或打开字幕文件，也可点「打开识别页」另存字幕。 |
| 中断恢复 | 队列记录保存在识别数据库。服务重启时未完成的批次标记为「已中断」，未处理项回到等待；重新打开批次即可继续。完成批次的历史保留在数据库中，批次页显示完整条目。删除批次会同时删除它的子会话与音频副本；重试未完成项时，只要旧音频副本还在就直接复用，不再重新解码源文件。 |
| 查看字幕 | 队列表格显示文件名、所在文件夹、状态、导出文件和译文进度；长文件名保留扩展名并用省略号缩短，悬停可看完整路径；译文列自适应加宽，`已译行/总行` 不会被截成省略号。选中一行后右侧可切换「字幕文件 / 译文」，点击任意字幕行会按该行时间码播放对应音频，再点停止；并可直接打开字幕文件、打开所在文件夹，或把选中记录的译文单独导出为 `<文件名>.<目标语言>.srt`。双击目标行或点「打开识别页」进入该项的普通识别页。 |
| 批次翻译 | 表格的「译文」列显示 `已译行/总行`，右侧预览显示当前译文；「复制批次 ID」和「复制 MCP 指令」给出 `list_translation_sessions(batch_id) → get_subtitle → save_translation` 的批次处理入口。MCP 译文只写回识别记录，不会自动覆盖已导出的原文字幕。 |

批量状态与单文件识别的互斥由 `Manager.require_idle_engine(..., recognition_owner=True)` 控制：批量线程持有整批的引擎预留，因此队列内部换文件时不会被其他任务抢走，而队列外的调用仍被拒绝。

## 音频翻译与 Agent

「翻译当前结果」把一段识别结果按行翻译成另一种语言，译文与原文字并列查看，并可单独导出 SRT。原识别文字、时间码与分行保持不变，译文存放在该识别记录的 `translation` 字段中，不会因为翻译失败而清空已有译文。0.8.0 起默认走翻译 Agent：先查术语和翻译记忆，再翻译剩余行并质检；关闭「使用翻译 Agent」仍走普通翻译。

| 部分 | 当前实现 |
| --- | --- |
| 提供方 | 「OpenAI 兼容 API」已打通；「本地模型（接口预留）」选择后会明确提示尚未接入，不会静默改走在线服务。接入本地模型时实现 `LocalTranslator.translate` 即可。 |
| API 设置 | Base URL、模型名与 API Key 保存在本机 `config.json` 的 `translation` 段；接口只回传 `has_key`，不把密钥送到界面或日志。Base URL 支持 `…/v1`、`…/chat/completions` 或服务根地址。 |
| 请求 | 每 20 行一批调用 `/chat/completions`，要求模型只返回与输入等长的 JSON 字符串数组；返回数量不符、非 JSON、HTTP 非 200 或超时都会给出具体错误，不写入半成品译文。整批行数错误时 Agent 会逐行重试一次。 |
| Agent | 检索启用术语，按原文子串匹配并注入提示词；精确命中翻译记忆的行直接复用；其余行分批翻译；随后检查行数、术语和数字，结果和 trace 写入 `agent_runs`。 |
| 术语库 | 原文、固定译法、语言对、说明、优先级、启用状态；新增重复词条会更新译法，删除只做软删除。翻译时按优先级取最多 100 条注入，避免提示词无限增长。 |
| 翻译记忆 | 按归一化原文 + 语言对精确查找；命中后使用次数加一，不重复请求模型；翻译成功后自动写入新行，可在知识库窗口查询或删除。 |
| Agent 指令 | 需要模型支持 `tools` / `tool_calls`；只能调用允许列表中的术语/记忆/当前字幕工具。查询、新增、修改、停用术语和删除记忆都有 trace；不能删除识别记录、音频或配置。 |
| 语言 | 英语、中文、日语、韩语、粤语、法语、德语、西班牙语、俄语、葡萄牙语、意大利语；默认英语，目标语言保存在设置中，下一次打开沿用。 |
| 导出 | 译文导出为独立的 `<文件名>.<目标语言>.srt`，由用户选择保存位置；原文 SRT 不受影响。识别页有译文时会出现独立的「导出中文字幕」，批量页选中记录后也能单独导出译文；两处都只写译文，不混原文。 |

翻译走网络或本地模型推理，不占识别引擎锁；但识别仍在进行时会拒绝翻译，避免翻译半截结果。术语/记忆保存在 `data/translation/translation.sqlite3`，Agent 运行记录最多保留最近 100 条。详细边界、工具和验收标准见[翻译 Agent 设计](TRANSLATION_AGENT.md)。

## 数据与模块

识别记录保存在 `data/recognition/recognition.sqlite3`，音频副本使用同目录的 UUID 文件名。批量队列保存在同一数据库的 `batches` 表：每项包含原文件路径、状态、识别记录 ID 与导出文件列表。重启服务时，上次未完成的识别任务会标记为中断，音频副本保留，可重新识别；未完成的批量标记为「已中断」，可继续。服务启动时会清理没有被任何会话引用的 WAV 副本。

最近作品从各自数据库只读汇总名称与状态，不合并数据库，也不复制音频。导入中的临时记录在成功后替换为正式任务，失败后移除并恢复原任务；导入期间切到其他记录，完成时只更新列表。

识别与音频编辑共用管理器的推理互斥：配音正在生成时，识别会提示等待；识别期间配音任务留在队列中。单文件识别结束时释放引擎进程；批量识别在整批结束后才释放，中间换文件复用同一进程，避免重复加载 ASR 与对齐器权重。识别与 AI 音频编辑也执行双向互斥检查；普通 WAV 裁剪可独立运行。忙碌时拒绝导入不会创建记录；重新识别失败时保留已有结果。

- `speech_recognition/lines.py`：时间戳换算、标点回填与分行规则。
- `speech_recognition/audio_import.py` 与 `decode_worker.py`：音频副本准备、独立 Qt 解码及坏文件清理，HTTP 服务不导入 Qt；`--video` 只改超时与提示，解码器仍然是同一个。
- `speech_recognition/runner.py`：同一引擎进程内的识别与对齐请求，含中文路径兼容。
- `speech_recognition/service.py`：模型选择、音频导入、执行、取消与重试；`batch=True` 是队列线程专用的引擎预留入口。
- `speech_recognition/batch.py`：批量队列、顺序执行、停止、重试与中断恢复。
- `speech_recognition/exporting.py`：SRT / TXT 生成、目标目录选择与同名字幕保护；`formats.py`：音视频后缀与文件选择过滤器。
- `speech_recognition/store.py`：独立 SQLite 会话与批量记录存储。
- `translation/service.py`：翻译提供方、OpenAI 兼容请求、分批解析与本地模型占位；`schemas.py` 与 `http_api/translation.py`：设置、术语/记忆与 Agent 接口。
- `translation/store.py`：术语、翻译记忆与 Agent 运行的 SQLite 存储；`translation/agent.py`：术语检索、记忆复用、质检、trace 与受控工具调用。
- `speech_recognition/reference_clip.py`：验证识别音频路径、裁剪独立参考片段；`desktop/controllers/recognition_references.py`：右键快照、后台准备与临时文件生命周期。
- `speech_recognition/schemas.py` 与 `http_api/recognition.py`：字段校验、批量接口与本机 API。

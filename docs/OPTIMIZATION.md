# 项目优化记录

2026-10-13：先处理草稿可靠性和引擎退出，再减少界面与数据库的重复工作。此轮为源码更新，发行包仍为 v0.7.28。

## 已完成

| 项目 | 改进 |
| :--- | :--- |
| 草稿保存 | 按任务排队，记录编辑版本；保存期间继续输入再切换任务，最新内容仍会提交。 |
| 失败恢复 | 待存快照写入 `pending-drafts.json`，重启后重试；打开任务时优先恢复本地待存稿。 |
| 生成与退出 | 提交失败恢复自动保存，提交期间继续编辑的内容另行保存；创建请求退出时先等待任务 ID。 |
| 引擎清理 | Windows 共用模型仍被映射时保留自有兼容路径，全部实例停止后重试；取消一个实例不会关闭其他实例。 |
| 健康检查 | SQL 直接统计未删除的排队 / 运行任务，不再反序列化历史记录，也不受 10,000 条上限影响。 |
| 设置刷新 | 模型与引擎页读取模型信息，音频页读取音频，性能页读取性能；常规页无需轮询请求。 |
| 输入校验 | 相同音色与参数去重，校验结果缓存 2 秒、最多 64 条；参数或相关文件版本变化立即重新检查。 |
| 对白状态 | 先按框 ID 分组历史，再更新各行；避免每行重复扫描整份历史。 |
| 模块职责 | 保存队列与声音校验独立成模块；网络线程只接收新建草稿的普通数据。 |
| API 文档 | 工作流音频 GET / HEAD 使用独立标识；原 URL 和交付规则兼容。 |

服务端生成前仍执行完整校验。草稿暂存不代替正式数据库；磁盘写入失败会显示错误并继续尝试 HTTP 保存。

## 本机测量

| 场景 | 优化前 | 优化后 |
| :--- | ---: | ---: |
| 现有数据库的健康检查队列统计 | 16.25 ms | 0.018 ms |
| 隔离的 10,000 片段状态查询与汇总 | 4.09 ms | 1.82 ms |

每项取 20 次的中位数。现有数据库以只读连接打开，规模样本使用临时数据库。这些数据只说明对应查询的开销，不代表模型推理或双语配音总耗时提升。

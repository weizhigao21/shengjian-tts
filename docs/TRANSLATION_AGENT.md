# 翻译 Agent 设计 · 声笺字幕翻译

版本：0.8.0 / 2026-11-25

## 1. 背景

现有字幕翻译框架已经打通 OpenAI 兼容 API，按 20 行一批逐行翻译，并把结果存进识别记录的 `translation` 字段。下一阶段引入翻译 Agent，但不能让自由对话的模型直接改字幕、删记录或操作文件。字幕翻译的硬约束是行数、时间码、术语一致性和可复现性，这些必须由确定性流水线保证。

因此本方案把“翻译”和“Agent”分开：

- **翻译器**：负责把一批字幕行翻译成等长的另一批行，不做规划，不碰数据库。
- **翻译 Agent**：负责查术语、复用翻译记忆、选择批次、质检、记录运行过程，并通过受控工具管理术语和记忆。
- **桌面界面**：保留逐行对照表，Agent 的状态、建议和工具调用过程可见，但最终写入仍由用户触发或明确确认。

## 2. 目标与非目标

### 目标

1. 建立可增删改查的术语库，翻译时自动检索并注入提示词。
2. 建立翻译记忆，完全相同的句子优先复用已有译文，减少重复请求。
3. 提供 Agent 翻译入口：检索术语 → 复用记忆 → 翻译剩余行 → 质检 → 写入记忆 → 生成运行记录。
4. 提供 Agent 运行追踪，用户能看到用了哪些术语、复用了多少行、哪些行有质检提示。
5. 提供受控的工具调用接口，让 Agent 在用户明确指令下增删改查术语和翻译记忆。
6. 不改变现有单文件/批量识别、字幕导出和普通翻译 API 的行为。

### 非目标

- 不允许 Agent 删除识别记录、音频、字幕文件或用户配置。
- 不允许 Agent 读取或回传 API Key，也不允许它执行任意 SQL、命令行或文件操作。
- 第一阶段不做多术语库项目隔离、术语自动导入、翻译版本分支和多人协作。
- 第一阶段不把整段字幕交给模型自由合并/拆分；行数必须保持。

## 3. 术语

| 名称 | 含义 |
| --- | --- |
| 术语库 | 原文词条到目标语言固定译法的映射，翻译时强制遵守。 |
| 翻译记忆 | 已确认的原文句子与译文对，用于精确复用和参考。 |
| Agent 运行 | 一次带追踪的翻译任务，包含工具步骤、命中数量、质检结果和耗时。 |
| 工具 | Agent 可以调用的受控函数，参数和返回值都有 JSON 结构。 |
| 草稿/结果 | 识别记录里的 `translation` 字段，只有成功完成后才整体写入；失败不留半成品。 |

## 4. 总体架构

```text
识别结果 lines
     │
     ▼
TranslationAgent.translate
     ├─ search_terms     查术语库（只读）
     ├─ search_memory    查翻译记忆（只读）
     ├─ translate_lines  调用 ApiTranslator / LocalTranslator（确定性、等长）
     ├─ review           行数、术语、数字检查
     ├─ remember         写入翻译记忆（可关闭）
     └─ run record       写入 agent_runs，返回 trace
     │
     ▼
识别记录 translation（整体写入）
     │
     ▼
桌面翻译对话框（逐行对照 / 导出 SRT）
```

Agent 对话是另一条受控入口：

```text
用户指令 → LLM 工具调用 → 允许列表中的工具 → 审计记录 → 返回结果
```

LLM 只负责选择工具和填写参数；真正的增删改查由服务端校验后执行，模型不能直接访问数据库。

## 5. 数据模型

数据保存在 `data/translation/translation.sqlite3`，与识别记录分开，避免翻译知识库影响识别数据库。

### terms

| 字段 | 说明 |
| --- | --- |
| `id` | UUID |
| `source` | 原文词条，必填，最长 500 |
| `target` | 固定译法，必填，最长 500 |
| `source_lang` / `target_lang` | 语言代码，空字符串表示不限 |
| `note` | 说明，最长 500 |
| `priority` | 0–100，数字越大越优先 |
| `enabled` | 1/0；删除为软删除 |
| `created` / `updated` | 时间戳 |

同一 `source + source_lang + target_lang` 只保留一条，重复新增时合并更新。

### memories

| 字段 | 说明 |
| --- | --- |
| `id` | UUID |
| `source_key` | 归一化后的原文，用于精确查找 |
| `source` / `target` | 原文与译文 |
| `source_lang` / `target_lang` | 语言代码 |
| `session_id` | 来源识别记录，可为空 |
| `provider` / `model` | 来源提供方与模型 |
| `quality` | 1 普通，2 用户确认 |
| `uses` | 被复用次数 |
| `created` / `updated` | 时间戳 |

精确匹配使用 `source_key + source_lang + target_lang`；同一组合重复写入时更新译文、质量和时间，不产生重复行。

### agent_runs

| 字段 | 说明 |
| --- | --- |
| `id` | UUID |
| `session_id` | 对应识别记录 |
| `target` / `provider` | 目标语言与提供方 |
| `status` | `running` / `done` / `failed` |
| `trace` | JSON 数组，逐步骤记录工具名、结果摘要、耗时 |
| `result` | JSON 摘要，不复制整段译文 |
| `error` | 失败信息 |
| `created` / `updated` | 时间戳 |

运行记录只保留最近 100 条，避免无限增长；清理时保留正在运行和最近完成的记录。

## 6. Agent 工具

所有工具都是显式函数，不允许模型拼接 SQL。

### 只读

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| `search_terms` | `query`, `target_lang`, `limit` | 命中的术语列表 |
| `list_terms` | `target_lang`, `enabled_only` | 术语列表 |
| `search_memory` | `query`, `target_lang`, `limit` | 记忆列表 |
| `get_subtitle` | `session_id`, `offset`, `limit` | 只含行号、时间码、原文，不含音频路径；可按 500 行分页 |

### 写入

| 工具 | 说明 |
| --- | --- |
| `add_term` | 新增术语；重复时只更新译法，保留原说明和优先级 |
| `update_term` | 修改译法、说明、优先级或启用状态 |
| `disable_term` | 软删除术语，不物理删除 |
| `add_memory` | 写入翻译记忆；重复时更新译文并保留来源 |
| `update_memory` | 修改已有记忆的译文、质量或启用状态 |
| `delete_memory` | 软删除记忆 |
| `correct_lines` | 修正当前识别记录的字幕文本，只改文字不改时间码；旧译文会失效 |

写入工具必须校验长度、语言代码和 ID 存在性；删除只做软删除。字幕修正一次最多 100 行，每行新文本最多 2000 字，且行号必须已存在。对话 Agent 每次最多执行 5 轮、8 次工具调用；超过上限直接停止并返回已完成的步骤。

## 7. Agent 翻译流程

1. **加载**：读取识别结果，确认没有正在识别、至少有 1 行；目标语言和提供方走现有校验。
2. **查术语**：按目标语言取启用术语，逐行做大小写不敏感的子串匹配，按优先级排序，最多取 100 条。
3. **查记忆**：对每行做归一化精确查找；命中则直接采用记忆译文，未命中进入翻译批次。
4. **翻译**：仅把未命中的非空行交给 `Translator`；术语表拼进 system prompt，要求原文出现术语时必须使用指定译法。原有 20 行分批、等长 JSON 校验不变。
5. **质检**：
   - 行数必须与识别结果一致；
   - 命中术语的源行，译文必须包含对应译法（拉丁字母大小写不敏感）；
   - 源行中的数字、百分号、时间码应在译文中保留；
   - 质检只标记问题，不擅自合并/拆分行。
6. **修复**：如果整批翻译出现行数错误，按单行重试；单行仍失败则整次翻译失败，不写入半成品。
7. **写记忆**：成功翻译后，对没有质检问题的非空行写入记忆；同一原文/语言组合已存在时更新译文，不新增重复行。`use_memory=false` 时既不读也不写。
8. **落库**：一次性写入识别记录的 `translation`，包含 `agent` 摘要和 `agent_run_id`；运行记录单独保存 trace。

失败策略：任何阶段异常都把本次 `agent_run` 标为 `failed`，识别记录保留上一次成功译文，不覆盖。

## 8. Agent 对话（工具调用）

`POST /translation/agent/chat` 接收自然语言指令，使用当前翻译 API 的模型；模型必须支持 OpenAI 兼容的 `tools` / `tool_calls`。请求体：

```json
{"message": "把“声笺”加入术语库，译作 Shengjian", "session_id": "可选", "target": "en"}
```

行为：

- 系统提示明确：只能使用给定工具；不得删除文件/记录；删除术语和记忆只能软删除；不得读取 API Key。用户要求校对或字幕中出现明确识别错误时，Agent 可主动调用 `correct_lines`；没有证据不得凭猜测改字。
- 工具调用结果回填给模型，模型继续决定下一步或给出最终答复。
- 返回 `reply`、`trace`、`run_id` 和本次工具结果摘要。
- 模型不支持工具调用、HTTP 失败、参数不合法时返回明确错误，不静默降级成普通聊天。
- 所有工具调用写入 `agent_runs.trace`，保留可审计记录。
- 修正字幕会清除基于旧原文的译文，回复中必须提醒用户重新翻译。

## 9. HTTP 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/translation/terms` | 查询术语，支持 `query` / `target` / `enabled_only` |
| POST | `/translation/terms` | 新增术语，201 |
| PATCH | `/translation/terms/{id}` | 修改术语 |
| DELETE | `/translation/terms/{id}` | 软删除术语 |
| GET | `/translation/memory` | 查询翻译记忆 |
| POST | `/translation/memory` | 手动新增记忆 |
| PATCH | `/translation/memory/{id}` | 修改记忆译文、质量或启用状态 |
| DELETE | `/translation/memory/{id}` | 软删除记忆 |
| PATCH | `/recognition/sessions/{id}/lines` | 修正字幕行文本；不改时间码，旧译文置空 |
| POST | `/translation/agent/translate` | Agent 翻译某个识别记录 |
| GET | `/translation/agent/runs` | 查询运行记录，可按 `session_id` 过滤 |
| GET | `/translation/agent/runs/{id}` | 查看单次运行 trace |
| POST | `/translation/agent/chat` | 自然语言工具调用 Agent |

术语/记忆不存在时返回 404 错误码 `TRANSLATION_TERM_NOT_FOUND` / `TRANSLATION_MEMORY_NOT_FOUND`；Agent 运行不存在时返回 `TRANSLATION_RUN_NOT_FOUND`。

## 10. 桌面界面

### 语音识别页

- 「音频翻译」分组保留「翻译当前结果…」，并增加「术语库 / 记忆…」直接入口；不需要先识别音频也能管理术语和记忆。
- 「批量识别」分组保持不变，翻译 Agent 不影响批量自动导出的原文；批量页选中记录后可单独导出译文 SRT。

### 翻译对话框

- 增加「使用翻译 Agent」复选框，默认开启；关闭时走原普通翻译接口。
- 开始翻译时调用 Agent 接口，结果表仍显示原文/译文，不改变导出逻辑。
- 状态行显示 Agent 摘要，例如“术语 4 条 · 记忆复用 2 行 · 质检提示 1 处 · 3.2 秒”；详细 trace 放在提示框。
- 增加「术语库 / 记忆」按钮，打开翻译知识库窗口。

### 翻译知识库窗口

三个页签：

1. **术语库**：搜索、新增、编辑、停用；每页 50 条，「加载更多术语」追加。单击行只选中，双击或点「编辑选中」才进入编辑；编辑时锁定原文、源语言和目标语言，保存后回到「新增术语」并把焦点放回原文，方便连续录入。同一原文 + 同一语言对再次新增只更新译法，保留原说明和优先级，状态栏会明确提示。
2. **翻译记忆**：搜索、查看来源、删除（软删除）；每页 50 条，第一次切到该页签才加载，之后用「刷新」手动更新，不再定时全表重拉。来源显示为「识别记录 xxxxxxxx」/provider/手动，完整 id 放在悬停提示。
3. **Agent 指令**：输入自然语言指令，发送后显示回复和工具调用 trace；可直接让 Agent 校对字幕、维护术语和记忆，不展示 API Key。修正字幕会清除旧译文，完成提示里会说明。

术语和记忆的搜索都有 350ms 防抖，输入时不会每敲一个字就发一次请求。

窗口只允许在本地服务已连接时打开；所有写操作走 HTTP API，不在界面里直接改 SQLite。

## 11. 安全与可靠性

- **最小权限**：Agent 工具只能访问术语、记忆、当前识别的文本；不能读写音频、配置、日志或任意文件。
- **软删除**：术语和记忆删除只置 `enabled=0`，可恢复；物理清理只由后续维护任务执行。
- **写入边界**：Agent 翻译写识别记录是用户点击“开始翻译”触发的；对话 Agent 只有在用户明确要求，或字幕中出现可验证的明确识别错误时才写入，不能凭猜测批量改文本。每次修正都记录旧文、新文和理由。
- **提示注入**：字幕内容视为数据，即使包含“删除术语/忽略规则”等文字，也不能作为工具指令执行。
- **密钥隔离**：翻译设置接口只返回 `has_key`；Agent 对话上下文不包含 API Key。
- **可复现**：温度 0；术语和记忆的命中记录在 trace 中；失败不覆盖旧译文。
- **长度限制**：术语/记忆字段 500 字；查询最多 200 条；Agent 对话最多 5 轮/8 次工具调用。

## 12. 分阶段范围

### 第一阶段（本次实现，0.8.0）

- 术语库、翻译记忆的 SQLite 存储与 CRUD API。
- Agent 翻译流水线：术语检索、记忆复用、术语注入、质检、记忆写入、运行 trace。
- Agent 工具调用对话（OpenAI 兼容 API，需模型支持 tools）。
- 翻译对话框的 Agent 开关、知识库窗口三个页签。
- 测试、API 文档和用户文档。

### 第二阶段（后续）

- 多术语库/项目隔离、CSV/JSON 导入导出、术语冲突合并界面。
- 翻译版本历史、逐行人工修订、译文对比视图。
- 本地模型工具调用适配；无工具调用能力时改用 JSON 计划模式。
- 术语自动发现和“建议新增术语”确认流。

## 13. 验收标准

1. 术语 CRUD：新增、查询、修改译法、软删除后不再参与翻译，重复新增不产生重复行。
2. 翻译记忆：写入、精确命中、使用次数增加、软删除后不再命中。
3. Agent 翻译：有术语时译文包含指定译法；记忆命中行不再请求模型；行数与时间码保持不变。
4. Agent 质检：数字/术语缺失出现在 trace 中，但不会自动合并或拆分行。
5. 普通翻译接口行为不变，旧测试全部通过。
6. Agent 对话在模型支持 tools 时能完成“新增术语/查询术语/停用术语”，所有调用有 trace；模型不支持时给出明确错误。
7. 关闭 Agent 开关时仍走原 `/translation` 接口，不受术语和记忆影响。
8. 术语/记忆数据只写 `data/translation`，不改识别数据库结构。

## 15. MCP 接入

0.9.1 在不改变本文边界的前提下，把同一套翻译知识库和 Agent 翻译暴露为 MCP 工具：外部 AI 客户端可以读字幕、管理术语和翻译记忆、触发翻译，也可以用自己的模型翻译后通过 `save_translation` 回写；但不能绕过服务层直接改 SQLite。MCP 进程只转发本机 HTTP，不创建 Manager，也不抢推理实例。工具清单、客户端配置和下一阶段 MCP Client 的约束见[《MCP 接入设计》](MCP_INTEGRATION.md)。

0.9.2 为外部回写补上可见性和记忆复用：识别页增加「原文 / 译文」标签；`save_translation` 在质检后把合格行写入翻译记忆；翻译窗口和记忆库轮询最新记录；旧版本已写入、但记忆为空的记录可用 `scripts/backfill_translation_memory.py` 补写，不重新调用模型。

0.9.3 修正导出：识别页切到「译文」后，「导出字幕」和「复制文字」都按当前标签页取译文，时间码沿用原文；按钮文字切换为「导出译文」，默认文件名带目标语言，避免与原文 SRT 互相覆盖。

0.9.4 收拢翻译知识库界面：移除内容区重复的关闭按钮和两个手动刷新按钮；默认只显示新增/发送主操作，术语或记忆选中后才显示修改、停用或删除动作；底部状态按当前页签独立，避免非活动页签的数据加载覆盖提示。

0.9.5 统一窗口标题区：音频翻译、批量识别和翻译知识库都不再在内容标题旁重复画关闭叉，只保留系统标题栏关闭；底部文字「关闭」保留。

0.9.6 批量识别支持拖入多个音频/视频；批量识别的每个文件仍是独立识别会话，会话摘要和 `get_subtitle` 增加 `batch_id`/`batch_index`，外部 MCP Agent 可按批次逐条翻译并回写。批量自动导出的 SRT 还是识别原文，译文需在结果页切到「译文」后导出。

0.9.7 批量识别窗口按文件数量收缩表格高度，去掉列表下方的大块空白；文件多时最多显示 9 行并在表格内滚动。
0.9.8 批量识别改为独立模式页，批次在任务目录中只占一条记录；页面逐文件显示字幕行数和译文进度，并提供「复制批次 ID」「复制 MCP 指令」。外部 Agent 仍按 `batch_id` 逐 session 读取、翻译、回写，不改变译文边界。

0.10.1 收紧 MCP 翻译的 token：`get_subtitle` 默认 compact 分页（50 行一块、默认不带时间码），带 `known_revision` 时原文未变只回 142B；`save_translation` / `translate_subtitle` 默认只回写回执，不再回显整段译文。语言代码统一归一，`zh-CN` 落库为 `zh`，`save_translation` 的 `target_lang` 改为必填。翻译 Agent 自身的分批、术语和记忆逻辑不变。

0.10.6 增加单独的中文字幕导出：识别页有译文时显示独立「导出中文字幕」按钮，批量页选中记录后也能导出译文 SRT；两处都只写译文，时间码沿用原文，空译文行跳过。批量自动导出的原文 SRT 保持不变。批量预览的字幕文件和译文都支持点击行跳播对应音频。

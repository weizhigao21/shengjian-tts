# CUDA Graph 本机验证 · 2026-10-17

结论：在下述 RTX 2080 Ti / Qwen3-TTS 1.7B Base 配置中，图重放将当前专用批量循环的热模型总耗时再减少约 50%，对应生成音频逐条字节一致。此处比较的是 `fixed` 与 `graph`，不代表相对原生 GGUF 引擎的倍率。模块仍为未发布实验，默认关闭，当前安装的 v0.7.50 未被替换。

## 条件和方法

- 测试实现：提交 `506a890`，正式 `qwen_fastpath.py` / `qwen_cuda_graph.py` / `qwen_worker.py`，不是早期独立原型；未修改 SDK 或模型权重。
- NVIDIA RTX 2080 Ti，11264 MiB；官方 Qwen3-TTS 1.7B Base 原始权重，FP16 / SDPA；PyTorch 2.9.0+cu128、qwen-tts 0.1.1、Transformers 4.57.3，CPU 线程 8。
- 相同声音预设 `voice-c00aca3a0764`（qw3-御姐）；同一参考音频与原文。种子 1234，最多 256 tokens，温度 0.9、Top K 50、Top P 1.0、重复惩罚 1.05；残差采样同样为 0.9 / 50 / 1.0。
- 文本采用内置测速的 20 条中文、10 中 / 10 英交替两组；每组 20 条，均按 8 / 8 / 4 处理。两种路径使用同一驻留模型和音色提示。
- 先预热固定循环及图重放的 8 条、4 条输入，再按 `fixed → graph → graph → fixed` 运行。每轮完整生成 20 条，计入同步后的实际推理与 WAV 写入耗时；读取哈希和音频验证在计时外。不使用成品缓存，不修改生成长度或采样参数。
- 热模型结果为每种路径两轮的平均值；平均每条 = 每轮耗时 / 20，是吞吐摊销，不代表独立请求的延迟。计时轮均无新增图录制。

首次加载模型、建立参考音色并生成一条为 14.1745 秒，仅说明该次进程启动，不是清空系统文件缓存后的冷启动。首次图准备并生成 8 条、4 条的完整调用分别为 3.0769、3.1263 秒，**包含生成本身，不能当作纯录制耗时**，未混入上述热模型均值。

两张图建立前后，PyTorch 常驻 allocated 增量为 18.3462 MiB；这是本次固定输入和参数组合的分配差，不是整个进程显存。计时轮 allocated 峰值中文约 5333 MiB、双语约 5521 MiB，reserved 峰值分别 5886、6538 MiB；固定循环对照期间保留同一图缓存，因此两者峰值不用于推算图自身的显存开销。

## 一致性、回退和取消

- GPU 编码对照：批大小 1 / 2 / 4 / 8，采样 0.9 / 50 / 1.0、采样 0.7 / 25 / 0.8、非采样三种配置，种子 1234 / 42 / 0，共 36 组。编码和后续 CUDA RNG 状态均相同，12 次录制、36 次真实重放。
- 实际 GPU 上通过抬高保护阈值触发低显存分支；通过注入 RuntimeError 触发可恢复录制失败。两者均报告 `fixed`、记录回退原因，编码和 RNG 状态与固定循环一致。恢复正常图缓存后，真实重放通过。未故意耗尽显存或破坏 CUDA 上下文。
- 真实 `BatchProcess` 首先完成 8 条图路径生成；下一请求开始 0.5 秒后取消，约 0.1008 秒内返回 CANCELLED 并退出工作进程，进程引用清空，没有本次取消的 WAV。新进程成功重新录制并生成有效 WAV，报告 `graph`。这是一次实测，不构成所有取消时机的延迟上界。
- 原有 211 项相关回归及 8 组小型 CPU 模型编码 / RNG 对比已通过；CPU 模拟测试覆盖失败、缓存边界和元数据，但不作为 GPU 性能证据。
- 各实验前后配置文件 SHA-256 一致。未写入用户作品、生成数据库或成品缓存；测试日志、音频与完整逐条报告位于项目 `artifacts/predictor-fastpath/`，测试结束后工作进程已退出。

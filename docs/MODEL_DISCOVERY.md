# 引擎模型扫描

v0.7.32 为 Vevo2 增加音频编辑适配。目录和已安装条目的 `edit_adapted=true` 表示可用于编辑页的换声 / 台词修改；`adapted` 仍表示原文章 / 对话的配音适配，两者独立。设置页提供「音频编辑」分类。其他扫描出的家族继续按各自实际适配状态显示。

在「设置 → 模型」识别当前 audio.cpp 引擎声明的模型，并核对官方仓库，补全下载目录。

![按用途筛选扫描结果](images/model-discovery.png)

## 使用

- 首次读取模型页或更换引擎时自动扫描；缓存一天内有效，过期后重新扫描。
- 点击「扫描支持模型」立即重扫，使用所选下载来源；ModelScope 的目录查询使用 Hugging Face 元数据。
- 在「模型目录」标题下按全部、语音生成、语音识别、时间对齐、音频编辑、其他音频或已适配分类，也可叠加搜索名称、精度或用途。多用途模型可出现在多个分类，按当前引擎的任务声明判断。
- 「支持详情」列出引擎声明的全部模型家族、用途及支持状态，包括尚无可校验 GGUF 下载的模型。
- 已下载和可下载列表显示发布时间；悬停查看完整的本地时间和来源，无法确认的日期显示「未知」。

## 下载任务与速度

v0.7.40 在已下载列表上方集中显示下载任务。有下载、校验、等待启用、暂停或失败的任务时出现，完成后自动移出；没有任务时整块隐藏。任务按进度更新，不受模型分类和搜索影响，正在下载的模型不会在目录中重复出现。

每项显示模型名称、精度、已接收 / 总大小、百分比、下载速度与状态；支持暂停、继续和失败重试。模型更新也在这里显示，继续时沿用版本文件目录，保留原模型。暂停记录重启后可从已有临时文件恢复。

速度显示为 B/s、KB/s 或 MB/s，按最近约两秒实际接收的字节计算。断点续传已有的内容不计入速度；服务器忽略续传请求时，重新下载的计数与速度同步重置。连接或等待数据时可能为零，停滞三秒后归零；校验、暂停与等待启用时显示「—」。

## 下载与配音

| 状态 | 行为 |
| :--- | :--- |
| 配音适配 | IndexTTS 2 / 2.5、VoxCPM2、Qwen3-TTS、Kokoro；下载并校验后添加到配音模型。 |
| 识别 / 对齐适配 | 引擎声明的 ASR 与对齐模型；下载并校验后进入识别模式的对应下拉框，不创建声音预设。 |
| 音频编辑适配 | Vevo2；下载并校验后可在音频编辑模式选择。 |
| 待适配，单文件 GGUF | 可下载、校验、查看和移除；仅保存模型，不创建声音预设，暂不能用于配音。 |
| 需要多个配套文件 | 展示已核对的文件信息；暂不支持自动安装完整包。 |

扫描不下载权重，也不改变现有声音预设。它依据**已选引擎随附的声明**，不会把最新上游版本的能力当成当前引擎已具备的能力。实验性、社区支持和开发中的状态在详情中保留。

## 缓存与失败恢复

缓存保存在数据目录的 `models/scan.json`，绑定引擎路径、文件版本及模型声明的文件签名。未变化的声明复用解析结果，轮询无需重复解析全部 JSON。

扫描固定仓库提交、文件大小和 SHA-256，保留既有模型 ID。新发现的模型下载到 `models/discovered/<模型ID>/`，避免不同仓库同名文件互相覆盖。原有模型及更新仍使用原路径规则。

断网保留已知目录；部分仓库失败保留其上一份结果并提示。自动失败后同一会话不反复联网，恢复网络后可手动重扫。扫描期间更换引擎会丢弃旧扫描结果，程序退出时停止扫描。

发布时间取**当前 GGUF 文件版本的仓库提交日期**，通过 [Hugging Face 文件元数据接口](https://huggingface.co/docs/huggingface_hub/en/package_reference/hf_api#huggingface_hub.HfApi.get_paths_info)按固定提交批量查询，每批最多 50 个文件。它描述的是 GGUF 文件版本的发布，原始模型的首发日期需另查模型公告。日期保存为 UTC，界面按本地时间显示。

旧缓存会后台补全日期。日期查询失败不影响模型列表和下载；文件内容相同时保留已知日期，内容变更且无法确认新日期时显示「未知」。安装记录保存对应文件日期，更新或回退时随实际文件切换。

若引擎缺少 `model_specs`，现有目录仍可使用；选择带声明的引擎版本后即可扫描。

## 接口与模块

`POST /models/scan` 接收 `{"source":"mirror"}`、`huggingface` 或 `modelscope`，返回 202。通过 `GET /models` 的 `scan` 读取进度与错误，完成后的结果合并到 `catalog`。

`model_scan.py` 负责发现与缓存；`model_updates.py` 负责官方仓库元数据校验；`model_management.py` 负责下载、安装记录与文件生命周期。目录中的“待适配”表示仍需新增生成参数、声音配置和请求适配，扫描本身不会完成这些适配。

v0.7.30 验证：350 项完整回归通过。本机 audio.cpp v0.9.1 的声明包含 112 个模型家族，官方仓库可核对 354 个 GGUF 文件；与原有目录合并后共 356 项，其中 263 项可自动下载，22 项已适配配音。数量随引擎及仓库变化；本轮仅验证扫描，不下载真实权重或执行额外推理。

v0.7.31 验证：362 项完整回归通过，覆盖日期批量查询、未知值、旧缓存补全、日期接口失败及模型下载 / 更新 / 回退。对上述 354 个 GGUF 文件的真实元数据查询均取得有效提交日期，未下载真实权重。
